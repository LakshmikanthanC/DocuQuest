# AI-Powered RAG Document Assistant

Upload PDF documents and ask questions in plain language. Answers are generated by an
LLM using **only** the retrieved chunks, and every answer comes back with the source
document and page so you can verify it.

username:admin@example.com
Password:admin12345


**Stack:** Next.js 16 · React 19 · TypeScript · Tailwind CSS v4 · FastAPI · LangChain ·
PyMuPDF · Sentence Transformers · ChromaDB · Ollama (Llama) · JWT · Docker

## How it works

```text
  PDF upload          Question
      │                  │
      ▼                  ▼
  PyMuPDF            Embedding
  text extract          │
      │                 ▼
      ▼             ChromaDB
  Chunking ◄──── similarity search
  (per page)            │
      │                 ▼
      ▼            top-k chunks
  Embeddings              │
      │                  ▼
      └───────►  Llama prompt
                      │
                      ▼
              Answer + source citations
```

**Hallucination reduction.** The prompt instructs the model to use only the supplied
context and to reply *"I could not find an answer to this question in the uploaded
documents."* when the context is insufficient. That marker is detected server-side and
the response is flagged `has_context: false`, which the UI surfaces as a warning. When
retrieval returns nothing at all, the LLM is never called.

**Accurate citations.** Pages are split individually rather than concatenated first, so
every chunk keeps its true page number and the UI can point at the exact page.

**Per-user isolation.** Every Chroma record is tagged with `user_id`, and every query
filters on it, so one account can never retrieve another's chunks.

## Running locally

### 1. Prerequisites

- Python 3.11+
- Node.js 20+
- [Ollama](https://ollama.com) running with a chat model

```bash
ollama serve                       # in one terminal
ollama pull llama3.1               # in another
```

### 2. Backend

```bash
cd backend
python -m venv .venv
.\.venv\Scripts\activate          # Windows
source .venv/bin/activate         # macOS / Linux

pip install -r requirements.txt
copy .env.example .env            # Windows: cp on macOS/Linux

uvicorn app.main:app --reload --port 8000
```

Interactive API docs: <http://localhost:8000/docs>

The first embedding request downloads `all-MiniLM-L6-v2` (~90 MB) into the Hugging Face
cache; subsequent starts are instant.

### 3. Frontend

```bash
cd frontend
npm install
cp .env.example .env.local        # Windows: copy

npm run dev
```

Open <http://localhost:3000>, create an account, upload a PDF, and ask a question.

### 4. With Docker

```bash
cp .env.example .env
docker compose up --build
```

The `ollama-pull` service pulls `llama3.1` automatically on first boot — expect a few
minutes. Override with `LLM_MODEL=llama3.2` in `.env` if you prefer a different model.

## Configuration

Every value has a working default; override in `backend/.env` or via compose.

| Variable | Default | Purpose |
|---|---|---|
| `SECRET_KEY` | `change-me-in-production` | JWT signing key — **change this** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `10080` | Token lifetime (7 days) |
| `CORS_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | Comma-separated allowed origins. **Set this in production** or browser requests are rejected |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama endpoint |
| `LLM_MODEL` | `llama3.1` | Chat model tag |
| `LLM_TEMPERATURE` | `0.1` | Low temperature keeps answers factual |
| `LLM_NUM_CTX` | `4096` | Context window |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Sentence-transformer tag |
| `CHUNK_SIZE` | `1000` | Characters per chunk |
| `CHUNK_OVERLAP` | `150` | Overlap between chunks |
| `RETRIEVAL_TOP_K` | `4` | Chunks passed to the LLM |
| `MAX_UPLOAD_MB` | `25` | Upload size limit |
| `MIN_RELEVANCE_SCORE` | `0.4` | Relevance floor. Chunks scoring below this are treated as no context and the LLM is not called |

Frontend: `NEXT_PUBLIC_API_URL` (default `http://localhost:8000/api`).

> `NEXT_PUBLIC_*` values are inlined at **build** time. Rebuild the frontend image after
> changing it.

### Tuning retrieval

| Symptom | Change |
|---|---|
| Answers miss relevant detail | `RETRIEVAL_TOP_K=6` |
| Answers blur across topics | `CHUNK_SIZE=700`, `CHUNK_OVERLAP=100` |
| Very long PDFs answer slowly | `CHUNK_SIZE=1500`, raise `LLM_NUM_CTX` |
| `Could not find an answer` too often | Lower `CHUNK_SIZE` so passages stay focused |

## API

All routes are prefixed with `/api`. Authenticated routes need
`Authorization: Bearer <token>`.

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/health` | LLM reachability, embedding model, document count |
| `POST` | `/api/auth/register` | Create an account, returns a token |
| `POST` | `/api/auth/login` | Sign in, returns a token |
| `GET` | `/api/auth/me` | Current user |
| `GET` | `/api/documents` | List your documents |
| `POST` | `/api/documents` | Upload a PDF (`multipart/form-data`, field `file`) |
| `GET` | `/api/documents/{id}` | Document metadata |
| `DELETE` | `/api/documents/{id}` | Delete a document and its vectors |
| `POST` | `/api/chat` | Ask a question |
| `GET` | `/api/chat/history` | Conversation for this session |
| `DELETE` | `/api/chat/history` | Clear the conversation |
| `DELETE` | `/api/chat/history/all` | Clear history, documents, and vectors |

**Ask a question**

```jsonc
// POST /api/chat
{
  "question": "What is machine learning?",
  "top_k": 4,                       // optional, defaults to RETRIEVAL_TOP_K
  "document_ids": ["a1b2c3"]        // optional, scopes retrieval
}
```

```jsonc
// Response
{
  "answer": "Machine learning is a subset of artificial intelligence…",
  "sources": [
    {
      "document_id": "a1b2c3",
      "filename": "research-paper.pdf",
      "page": 3,
      "chunk_index": 7,
      "snippet": "Machine learning is a subset of artificial…",
      "score": 0.87
    }
  ],
  "has_context": true,
  "model": "llama3.1"
}
```

## Implementation notes

**Backend**

- Uploads stream to disk in 1 MB blocks and abort if they exceed `MAX_UPLOAD_MB`.
- Indexing runs as a FastAPI background task, so uploads return immediately; the
  frontend polls while `status` is `processing`. A failure sets `status: failed`
  instead of raising.
- Pages that yield no text are skipped, so scanned image-only PDFs produce no chunks
  rather than garbage.
- Chroma distance is converted to a `0–1` similarity score for display. That transform
  is hyperbolic, so it bottoms out near `0.33` for normalised vectors; `MIN_RELEVANCE_SCORE`
  defaults to `0.4`, the same boundary the frontend labels "weak match". Unrelated
  questions are therefore rejected before the LLM is called, rather than by asking the
  model to decline.
- CORS origins come from `CORS_ORIGINS`. The default covers local development only, so
  set it explicitly when deploying or browser requests will be rejected.
- Users and documents are stored in JSON files, keeping the app runnable with no external
  database. Writes are atomic (temp file plus `os.replace`), and a corrupt file is moved
  to `<name>.corrupt` and logged rather than silently discarding every record.
  Both stores are in-process, so run a single Uvicorn worker; swap
  `app/services/user_service.py` for SQLAlchemy to move to PostgreSQL.
- Chroma rejects a `where` clause with more than one top-level key, so multi-field
  filters are combined with `$and`.

**Frontend**

- `'use client'` is applied only to the interactive components; `app/page.tsx` stays a
  server component.
- The JWT lives in `localStorage`, matching the documented pattern for browser-only
  client components. For a public deployment, move it to an `httpOnly` cookie.
- `app/error.tsx` uses the Next 16 `retry` prop, and `app/layout.tsx` uses the global
  `LayoutProps<"/">` helper.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Cannot reach the backend` | Start FastAPI, or point `NEXT_PUBLIC_API_URL` at the right host |
| Health shows `llama3.1 (offline)` | `ollama serve` and `ollama pull llama3.1` |
| `No supporting context was found` | Ask something the document actually covers, or lower `CHUNK_SIZE` |
| First upload is slow | First run downloads the embedding model |
| `Could not validate credentials` | Token expired — sign in again |
| Chroma dimension error | Delete `backend/chroma_db/` and re-upload after changing `EMBEDDING_MODEL` |
